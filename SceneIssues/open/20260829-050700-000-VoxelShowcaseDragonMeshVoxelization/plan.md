# Plan — VoxelShowcase Dragon Mesh Voxelization

## Acceptance / ownership
`VoxelShowcase` needs a reusable **authoring-time** conventional triangle-mesh → canonical voxel path, proved on a legitimately redistributable detailed curved winged dragon. Runtime must load/replay only baked sparse cells through normal voxel storage so rendering, collision, edits, and destruction share world truth. Matched source/voxel built-player evidence must be judged `production-quality`.

## Architecture / discriminator
Hypothesis A: `IStructureAuthoringSession` and normal structure storage remain authoritative; the missing capability is deterministic offline conversion plus composition wiring. Hypothesis B: an existing arbitrary mesh/SDF importer should be generalized. Result: **A supported; B rejected.** Generic implementation remains under `Structures/Runtime/MeshImport`: transformed triangles → conservative surface coverage → bounded closed-interior fill → deterministic material ownership → ordered sparse bake/codec → canonical authoring replay. Unity hierarchy/skinned adaptation is editor-only. Shared importer/metrics APIs contain no dragon/source/showcase policy, and independent non-dragon reuse is covered.

Input ownership is also separated: `StructurePlacementSelection` owns one-shot selection/commit state and `StructurePlacementInputRouter` owns control-consumption policy. Live `VoxelShowcase` call-site wiring remains incomplete because the connected whole-file writer cannot safely edit the large canonical scene owner from truncated reads; do not bypass this with reflection or a competing controller. Built-player feature proof must use the module-owned validation-scene architecture recorded for this issue rather than the Worldbuilding Gallery/top-level showcase as a test fixture; production integration still remains required by acceptance.

## Source / blockers
The user-provided `mountain_dragon_supported.zip` contains a 2,144,152-triangle CHITUBOX STL. Connectivity cleanup retained a 1,763,914-triangle dragon/scenic-base component. Deterministic 0.5-unit vertex clustering produced a conventional OBJ with 13,431 vertices / 29,734 triangles, 860,349 bytes, SHA-256 `f1f44d59f7d9c775b600ac0b9ad066a15a3c652bf685a12b2344b8c383ff12b1`, gzip SHA-256 `fd2f8253fcf5bc32b275640448511f59d20dcc7d01c307f99124b224431892d4`.

Repeated reconstruction failures are isolated to source-transfer packaging rather than the decoder. Run `33362323833` proved the historical segmented logical `part13` reconstructed to the wrong gzip identity. Run `33364246307` then proved mixed whole+segmented transport fails closed as intended. After stale segments were removed, run `33364871767` proved the remaining whole `part13` is still malformed: the archive totals 319,999 Base64 characters rather than 320,000.

History-side minimal-repro work now proves the one-character loss predates every repair attempt. The originally vendored whole `part13` blob `eadac3aa83e74de30695e7d531af63e917745d77` is 19,999 bytes; the first repair truncated it to a 9,999-byte blob, and the second repair merely restored the same malformed 19,999-byte blob. No known-good 20,000-byte whole exists in branch history. The historical segmented form totals 20,000 (`part13.00` 4,999 + `part13.01` 10,000 + `part13.02` 5,001) but already failed the pinned gzip hash, so length alone is not accepted as correctness. Commit `b9b2e627` (`Stage missing dragon source segment`) added the 5,001-byte tail later used as `part13.02`; it is not the missing single character. The deliberate `_probe13first5k` transfer probe is exactly 4,999 bytes and matches historical `part13.00`, localizing the demonstrated transfer loss to the intended 5k probe boundary.

Because the same exact-source acceptance failed after materially different fixes, do not mutate the source again until the minimal repro proves the correction. `MountainDragonSourceArchiveTests.DiagnosePart13TransferLoss_MissingProbeBoundaryCharacterHasUniquePinnedIdentity` searches only the 64 Base64 characters at that demonstrated 4,999-character boundary and accepts a candidate only if the complete stream matches the pinned gzip SHA-256 and the decompressed 860,349-byte OBJ SHA-256. If this bounded discriminator fails, broaden root-cause isolation before another source edit. The production reconstruction adapter remains strict and unchanged; runtime never reads source triangles.

Exact provenance is independently blocked: the user states the model was free and usable, but source URL, author, and named license/permission text are unavailable. Do not close licensing acceptance without them.

The STL/derived OBJ has no standard source material regions. Composition now deterministically maps unmaterialed source/interior cells to canonical `DarkStone` via `MountainDragonPalettePolicy`/`MountainDragonAuthoringPolicy`; this is explicit showcase palette mapping, not preservation of absent source color. Existing/future real source material IDs pass through unchanged.
