# Plan — VoxelShowcase Dragon Mesh Voxelization

## Acceptance / ownership
`VoxelShowcase` needs a reusable **authoring-time** conventional triangle-mesh → canonical voxel path, proved on a legitimately redistributable detailed curved winged dragon. Runtime must load/replay only baked sparse cells through normal voxel storage so rendering, collision, edits, and destruction share world truth. Matched source/voxel built-player evidence must be judged `production-quality`.

## Architecture / discriminator
Hypothesis A: `IStructureAuthoringSession` and normal structure storage remain authoritative; the missing capability is deterministic offline conversion plus composition wiring. Hypothesis B: an existing arbitrary mesh/SDF importer should be generalized. Result: **A supported; B rejected.** Generic implementation remains under `Structures/Runtime/MeshImport`: transformed triangles → conservative surface coverage → bounded closed-interior fill → deterministic material ownership → ordered sparse bake/codec → canonical authoring replay. Unity hierarchy/skinned adaptation is editor-only. Shared importer/metrics APIs contain no dragon/source/showcase policy, and independent non-dragon reuse is covered.

Input ownership is separated: `StructurePlacementSelection` owns one-shot selection/commit state and `StructurePlacementInputRouter` owns control-consumption policy. Live `VoxelShowcase` wires those existing seams directly in the canonical scene owner: `B` enters/cancels placement, wheel selection is consumed only while active, Space commits once, and ordinary jump/fly/brush controls remain unchanged outside placement mode. The first exact-SHA validation exposed a missing `VoxelEngine.Structures.Runtime` assembly reference; that cause was fixed rather than retried unchanged, and exact-parent CI run `33416544070` subsequently passed for feature SHA `8eade9790b200478e113e440536f47b1ca378355`.

Built-player feature proof must use a module-owned validation scene/fixture and instantiate the same production systems used in the real game rather than substitutes. The top-level showcase and Worldbuilding Gallery are not feature test fixtures. Production `VoxelShowcase` integration remains separately required by acceptance.

## Source / blockers
The authoritative user upload has been re-located in the ChatGPT file Library as `mountain_dragon_supported.zip` (50,524,579 bytes, uploaded 2026-08-30). It was materialized and verified directly: ZIP SHA-256 `f48cab5ab5b7edf6a84cc7bf14797c73d0ac61bf597ef76a587589a4522aeb0f`; the archive contains exactly `mountain_dragon_supported.stl`, 107,207,684 bytes, CHITUBOX binary STL, SHA-256 `a01f600705a6daf79a8828474f227251a5680d4bb8bad4aa46659f9e06cf53d6`. This resolves the prior external source-byte availability blocker; do not go back to the contradictory historical repository transfer as source authority.

Earlier work on the same upload identified a 2,144,152-triangle STL and a dominant support-free dragon/scenic-base source. The documented 0.5-unit clustering derivation was re-run directly from the recovered STL and independently reproduces the recorded geometric cardinality after compaction: 13,431 used vertex clusters and 29,734 unique non-degenerate triangles. The historical OBJ byte serializer itself is not present in the repository, so its 860,349-byte / `f1f44d59f7d9c775b600ac0b9ad066a15a3c652bf685a12b2344b8c383ff12b1` byte identity cannot be regenerated merely from the prose recipe without choosing a text serialization. Preserve that recorded identity as evidence; do not falsely claim a newly serialized OBJ is byte-identical unless its hash actually matches.

Repeated reconstruction failures were isolated to repository source-transfer packaging rather than the decoder. Run `33362323833` proved the historical segmented logical `part13` reconstructed to the wrong gzip identity. Run `33364246307` proved mixed whole+segmented transport fails closed as intended. Run `33364871767` proved the remaining whole `part13` was malformed, and exact-SHA run `33377081586` / job `99440882707` proved historical/current transfer variants are contradictory. That discriminator still stands for repository-history reconstruction, but it is no longer a source-availability blocker.

The immediate source-vendoring blocker is execution transport rather than missing source bytes: this agent can materialize and process the recovered 50.5 MB archive locally, while the connected GitHub write surface accepts inline UTF-8 content and has no local-file/binary upload action. The derived source archive must not be replaced by known-corrupt historical parts merely to satisfy the checkbox. Leave source vendoring unchecked until exact derived bytes can be committed through a byte-capable repository path or an equivalently validated compact deterministic derivation is deliberately committed and pinned.

Exact provenance is still independently blocked: the user states the model was free and usable, but source URL, author, and named license/permission text are unavailable. Do not close licensing acceptance without them.

The STL/derived OBJ has no standard source material regions. Composition deterministically maps unmaterialed source/interior cells to canonical `DarkStone` via `MountainDragonPalettePolicy`/`MountainDragonAuthoringPolicy`; this is explicit showcase palette mapping, not preservation of absent source color. Existing/future real source material IDs pass through unchanged.

## Current state / next work / gates
The shared importer has explicit `VoxelShellFill` semantics independently covered by non-dragon topology regressions: topologically open input may fill only when conservative rasterization itself encloses voxel-space cells, while genuinely open rasters remain unfilled and `Reject`/`SurfaceOnly` semantics remain unchanged. The dragon composition explicitly opts into that policy at `0.30` source units/voxel with X/Z <=127, Y <=511 and no global thin-feature dilation.

Canonical production placement integration is complete and compile-validated on exact SHA. Deterministic bake metrics plumbing now emits a UTF-8 sidecar from the production bake generator containing source triangle count, voxel size, grid/bounds, dense envelope cells, authored/surface voxel counts, connected components, material count, sparse brick count, topology facts, voxelization duration, and serialized bytes. `MountainDragonBakeGenerationTests.FormatMetrics_EmitsStableStructuralFactsWithoutPinnedSource` covers the formatter without requiring the blocked dragon source. Built-player resident/runtime placement/build cost is deliberately not fabricated and remains a later evidence gate.

Source identity is verified from the recovered upload, and the compact derivation's geometric counts are independently reproduced. The next source-dependent step remains committing a valid reconstructable source archive, then generating the production bake and dragon-anatomy assertions from those exact committed bytes. The matched `Mesh -> Voxels` staging, module-owned built-player dragon fixture, real 10-view capture integration, destruction/world-truth proof, and final cost evidence all remain artifact-dependent. Exact provenance remains a separate blocker and acceptance is unchanged.
