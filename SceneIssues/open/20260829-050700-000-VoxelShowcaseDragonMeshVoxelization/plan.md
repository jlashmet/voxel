# Plan — VoxelShowcase Dragon Mesh Voxelization

## Observed requirement / acceptance
Add a reusable authoring-time triangle-mesh → canonical sparse voxel pipeline, prove it on a **downloaded third-party** detailed curved **winged** dragon, and present matched source/voxel views in built `VoxelShowcase`. Runtime gameplay truth remains discrete voxel storage; the source mesh is authoring/reference/comparison only. Required proof includes conservative triangle coverage, solid fill, transforms/mirroring, material regions, thin features, deterministic sparse bake/replay, one-shot showcase placement, provenance, dragon anatomy regression, similarity metrics, destruction/world-truth evidence, cost metrics, required built-player captures, and direct human review. Current `AGENTS.md` additionally requires player-visible evidence to be explicitly judged `production-quality`; lower visual classifications do not pass this issue.

## Hypotheses / discriminator
A. Existing structure authoring/storage is already the canonical runtime path; missing work is reusable triangle rasterization/fill + sparse bake codec + showcase adapter.
B. An existing arbitrary mesh/SDF importer already owns this conversion.

Result: **A supported; B rejected.** Canonical replay is `IStructureAuthoringSession.Set` via structure composition; rendering/collision/editing derive from that storage.

## Selected implementation
Keep conversion additive under `Structures/Runtime/MeshImport`: transformed vertices → conservative triangle/AABB coverage → bounded exterior flood fill when valid → deterministic material ownership → ordered sparse cells → stable codec → `IStructureAuthoringSession` replay. Preflight invalid indices/non-finite transforms, X/Z<=127, Y<=511, and dense working-set budget before allocation. No runtime mesh voxelization or `MeshCollider` gameplay fallback.

Behavior-first importer/topology contracts and the Unity hierarchy adapter are on the branch. Existing focused tests already cover curved closed surface/fill, stable repeat conversion, transformed/mirrored input, deterministic material regions, thin sheets, invalid indices/oversized bounds, sparse-codec round trip, canonical replay, one-shot selection, and explicit open-topology fallback/rejection. Add the remaining non-finite-transform regression plus dragon-specific production regression after the source is vendored. Exact-SHA CI remains pending.

## Source dragon / licensing
**Chosen source:** Delatronic, `Dragon`, Blend Swap asset 15891 (historic URL id 80766), Blender 2.7x/Cycles, CC-BY. Current Blend Swap metadata describes the model as detailed; reviewer comments explicitly call out the wings and mesh flow. Benedikt Bitterli's Rendering Resources redistributed/cleaned this scene and exported the geometry for renderer use. Microsoft's `DirectX-Graphics-Samples` redistributes that same Delatronic scene as PBRT/PLY and includes an asset-specific `LICENSE.txt` stating CC-BY, original author, upstream source, and modification provenance. The PBRT scene identifies four dragon-material meshes (`Mesh008`, `Mesh013`, `Mesh014`, `Mesh015`), distinct teeth material, and a single shared scene transform. The Microsoft files are real non-LFS payloads (dragon parts include multi-megabyte binary PLYs), so this is the preferred auditable redistribution mirror.

Rejected candidates remain documented rather than silently substituted: OpenGameArt artist_71 `A three headed lizard or dragon creature` is CC-BY 4.0/~24k tris but has no wings; Cethiel/Drummyfish's CC0 winged dragon is legitimately redistributable but its mirrored DAE is only about 633 position vertices and is visibly low-poly, below this issue's detailed/production-quality gate. Artec 3D's CC-BY fantasy dragon is extremely detailed (~5M faces) but unnecessarily large now that the Delatronic mirror is verified.

**Current tooling blocker:** the connected GitHub reader can verify metadata/license and base64-encode binary PLY content, but response-size limits prevent lossless transfer of the multi-megabyte binary dragon meshes into this repository, and the execution container cannot directly download the external/raw hosts. Do not replace the selected model with lower-quality geometry to fit tooling. Once bytes are transferable, commit the exact source representation plus URL/author/license/original format, vertex/triangle counts, SHA-256, mirror commit/blob provenance, and required CC-BY attribution/license text.
