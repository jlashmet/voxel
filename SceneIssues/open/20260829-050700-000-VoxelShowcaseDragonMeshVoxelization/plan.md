# Plan — VoxelShowcase Dragon Mesh Voxelization

## Acceptance
Build a reusable mesh→voxel authoring pipeline that consumes ordinary transformed triangle geometry, conservatively covers triangle surfaces, optionally fills closed interiors, preserves deterministic material regions/thin features, and emits a bounded sparse baked structure. Runtime gameplay must load only that baked structure and replay it through the canonical `IStructureAuthoringSession`/storage path used by rendering, collision, edits, and destruction. Prove the path with a detailed curved dragon source mesh (>=20,000 triangles), a dedicated `VoxelShowcase` comparison/spawn path, deterministic metrics, and built-player evidence.

## Hypotheses and discriminator
A. Existing structure authoring/storage provides the canonical runtime path; the missing piece is a reusable triangle rasterizer/interior-fill baker plus authored sparse-artifact codec and showcase presentation.
B. Existing mesh/SDF utilities already rasterize arbitrary triangle meshes and should be reused/generalized.

Discriminator result: **A is supported; B is rejected on this revision.** No existing arbitrary-mesh voxelizer was found. The canonical public seam is `VoxelEngine.Structures.Api.IStructureAuthoringSession`, implemented by `VoxelEngine.Structures.Runtime.StructureAuthoringSession`, which delegates to `VoxelBrush` and preserves write-budget accounting. `VoxelEngine.Composition.StructuresComposition.CreateAuthoringSession(...)` is the application factory. The current repository has no generic `BeginAuthoringStructure`/`StructureLoader` persistence API, so the assignment's “or equivalent” path is: deterministic mesh conversion → serialized sparse authored-cell artifact → loader/codec → replay through `IStructureAuthoringSession.Set` → normal storage publication. No runtime mesh collider, SDF, or triangle gameplay truth is introduced.

Keep conversion logic in an additive reusable mesh-voxelization assembly using deterministic `Unity.Mathematics`/plain data. Unity/glTF extraction is an authoring adapter; runtime uses the same codec only to load already-baked cells and may render the source mesh solely as labeled comparison evidence.

## Source dragon / licensing
External candidates were investigated first. Sketchfab `Black Ink Dragon - Stylized Model` by Meleagor is CC-BY and 21.6k triangles but its binary download is authentication-gated here. OpenGameArt `A three headed lizard or dragon creature` by artist_71 is CC-BY 4.0 and ~24k triangles, but the 31.7 MB revised archive cannot be transferred through this execution surface. Khronos' Stanford dragon is directly hosted but carries the Stanford Graphics Library non-commercial restriction, so it is not the preferred shipping source.

To keep the feature self-contained and redistribution-safe, the committed source will therefore be an **original conventional curved dragon mesh authored for this feature and dedicated CC0-1.0**, stored as glTF 2.0 JSON with an embedded binary buffer. It must contain >=20,000 real indexed triangles (not duplicated/count-padding faces), recognizable head/neck/body, two wings with negative spaces, four feet/legs, horns/spines, and a curved tail. The source remains ordinary triangle input; the importer cannot contain dragon-specific geometry rules. Provenance, exact triangle/vertex counts, material colors, SHA-256, and CC0 notice are committed alongside it.

## VoxelShowcase integration

The live driver currently uses Space for jump/fly and unmodified mouse-wheel for brush radius; there is no existing structure picker/commit state despite the issue text. Add an explicit structure-selection mode so ordinary movement remains unchanged: entering selection exposes the dragon choice, wheel changes selection while active, and Space commits the selected baked structure exactly once. Repeated idle frames cannot duplicate a spawn because placement is edge-triggered and the selection records committed state. Tests exercise the same public selection/commit operations as keyboard input.

## Constraints / blast radius / cost
Authoritative output is deterministic CPU-side discrete voxel occupancy/material state. Expensive voxelization is authoring/editor-side only. Runtime may load/display the source mesh only in the labeled comparison exhibit; gameplay collision/destruction must query voxel storage exclusively. Keep changes additive to mesh-import/structure-showcase files; do not alter terrain/building generation semantics, global storage layout, collision, edits, or `.github/test-request.json` on the feature branch. Preflight transformed bounds, dimension caps (X/Z <=127, Y<=511), dense-cell budget, triangle/index validity, finite transforms, and fill policy before allocation. Record import time, triangle count, resolution, authored voxel count, serialized size, and runtime placement cost.

Do not close until every checkbox is validated and metadata is complete.
