Exact-parent run `33484111346` was fully green: requested Dragon tests, automatic module EditMode gates, Dragon and Kentridge built players, top-level SceneIssue replay, and final exact-SHA status all passed. The Dragon player produced exactly ten semantic screenshots and again authored all 98,100 cells without runtime exceptions. Direct human inspection still rejected the captures: the authoritative right viewport remained blank/tiny in multiple views. Because this is the same visual acceptance symptom after a materially different camera-selection fix, no third speculative fix is allowed.

Minimal renderer root cause is now isolated in production code. `VoxelRenderFeature.AddRenderPasses` enqueues the shared `VoxelRenderPass` for every non-preview camera; `MainCamera` tagging is not consulted. `VoxelRenderPass` owns one `VoxelSurfaceScheduler` instance. On the first camera rendered in a frame, `VoxelSurfaceScheduler.Prepare` advances clipmap movement, discovery, build admission, uploads, and visibility around that camera. For every later camera in the same frame, `_lastAdvancedFrame == frame` causes `Prepare` to call only `CollectVisibility` and return. `CollectVisibility` does not move an existing clipmap or admit/build geometry around the later camera; it only filters the first camera's already-known/ready chunks. The fixture creates the source camera first and the source/voxel exhibits are ~110.6 m apart, so the presentation camera owns scheduler advancement and the voxel camera cannot obtain ready geometry around its own target in that frame. This exactly explains the blank authoritative viewport and why changing only the `MainCamera` tag had no effect.

The root-cause-driven fixture repair is to make the authoritative voxel camera explicitly render first (create it first and assign a lower camera depth), so production surface advancement occurs around voxel truth. The presentation-only source camera renders second; it needs only ordinary mesh rasterization and can tolerate the voxel scheduler's later-camera visibility-only behavior. This changes validation composition only; no renderer/shared engine behavior should change.

A separate composition defect remains: `VoxelShowcase.TryPlaceSelectedStructure` still requires optional inspector `m_MountainDragonVoxelBake` and generic-codec decoding, while `MountainDragonBakedArtifact.Load()` already owns the pinned runtime transport. Repair this in Showcase composition only; do not teach the shared codec Dragon/MDVP policy.
