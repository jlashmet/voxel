## Current demonstrated blocker and root-cause gate
The continuing player failure is now correctly localized before extraction admission, not in count-batch sealing. `phases=0x2` is a bitmask representing active request phase 1 (`_stageAdmissionPending`). In exact post-master run `33824047466` on source `a01e8bd3e2b8659225ebb7373516e7e0ebe57681`, the workflow and 180-second process are green, yet artifact `9920411113` reaches only `MACROEVIDENCE content-ready target=moordell`; there is no `capture-ready`, no later macro target, and no dedicated macro evidence file. Therefore process success is not closure evidence and the latest master did not remove the liveness boundary.

Because the same acceptance symptom survived the materially different coverage-radius, survey-demand, and count-batch corrections, no further renderer production change is allowed until the independent minimal repro confirms the next root cause. `GpuSurfaceMirrorRelocationLivenessTests.DistantRelocationCannotLeaveEveryGpuWorkerAdmissionPending` performs a 384 m relocation and fails only when pending work remains while all eight demanded GPU chains stay stage-admission pending with zero active extraction for 20 seconds. Its diagnostics include ready/pending/demand/active counts, resident mixed slots versus mirror capacity, GPU-completion delta, and visible/missing counts.

A static candidate exists but is intentionally not yet selected as the fix: `GpuSurfaceMirrorCoordinator.ApplyChange` removes a non-active changed block from ready/mixed tracking while retaining its old mirror entry; if demand is then cancelled before recovery republishes, the stale recovery is discarded and the mirror slot may become untracked for eviction. The relocation repro must distinguish that bookkeeping leak from capacity pressure before production code changes. If confirmed, use the smallest lifecycle correction that frees only stale non-active mirror entries while preserving in-flight active dispatch, all capacities, fences, one-dispatch-per-frame backpressure, and GPU/device budgets.

Rejected alternatives remain: do not widen Kentridge load radius, weaken `HasCompletePublishedNearSurfaceCoverage`, increase extraction concurrency/device budgets, hardcode settlement-specific renderer policy, substitute top-level showcase scenes for required module validation, or rerun a known acceptance-red source as proof.
