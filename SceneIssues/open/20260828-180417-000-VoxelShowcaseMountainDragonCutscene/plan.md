## Hot-path discriminator / optimization sequence
The realized mountain program contains one large core `Fill` frustum plus many convex shoulder/support frusta. `PrimitiveRasteriser` already fast-pathed canonical-empty box carve and fully covered Uniform box carve, but a fully interior frustum `Fill` into canonical Empty still performed 512 identical containment/read/write iterations per 8^3 storage block. Regression `FrustumFillAtomicallyAuthorsFullyInteriorEmptyBlockWithoutOverfillingBoundaryBlock` was added before that optimization and corrected for region-local reads at `0bbf30043ccc...`.

Production commit `090d0032456e...` added a conservative frustum-fill fast path: a complete canonical-empty block is atomically authored only when all eight extreme voxel centres are inside the convex frustum. The emitted `VoxelCell` exactly matches the existing Fill semantics and logical accounting remains 512 writes. Partial/non-empty blocks, all other modes/shapes, primitive ordering, and the boundary-halo pass remained unchanged.

Exact request `5cc2ef4e03ce...` (parent/source `bf376936ae66...`), run `33288586966`, proved that change insufficient: cache miss, ~63.1 s cold asset import, then the fresh bake was killed at 241 s / 10.1 GB before the focused test. The fallback player correctly rejected the stale startup payload because the source-matched provenance manifest was absent.

The next discriminator was the unchanged curved `RasteriseBoundaryHalo` pass. It called `TryBoundaryDistanceQ4` (including integer square-root work for frusta) for every voxel in every expanded frustum bounds block, then discarded deep-interior samples with `abs(distanceQ4) > 32`. For a convex frustum, a complete 8^3 block whose eight extreme voxel centres all have signed interior distance >32 Q4 cannot contain a boundary-halo sample: radial clearance is minimized at a rectangular radial-plane corner, axial cap clearance is minimized at an axial endpoint, and frustum radius varies monotonically between the two axial endpoints.

Before production implementation, commit `b17d748f149b...` strengthened the focused regression to require both sides of the authored frustum boundary halo (positive solid-side and negative empty-side samples) while also proving a deep-interior cell has no authored boundary metadata. Production commit `da45c64e9658...` skips only complete `Fill + Frustum` halo blocks whose eight extreme centres all exceed +32 Q4. It replaces up to 512 signed-distance/integer-sqrt evaluations with eight corner evaluations; near-surface, partial, outside, carve, paint, and non-frustum blocks retain the exact previous per-voxel halo path.

Exact request `cda51cb0a62a...` (parent/source `408a0fdf8c2b...`), run `33289023179`, proved the halo optimization insufficient as well: ~65.5 s Asset Pipeline refresh, then the source-matched startup bake was killed at the same 241 s subprocess watchdog with roughly 10.5 GB peak RSS before the focused test. The fallback player again built but correctly rejected the stale payload for missing source-matched bake provenance, so its six captures are non-acceptance evidence.

Repository inspection exposed the missed dominant mode: `WorldBuilderMountainLandmarkCatalogue` emits the single core as `PrimitiveMode.Fill`, but the three asymmetric shoulders and the 20+ segmented path-support frusta as `PrimitiveMode.FillIfEmpty`. The two previous frustum optimizations therefore accelerated primarily the core and left almost all support authoring on the 512-cell path. Storage semantics make a narrow exact block optimization possible for a fully contained `FillIfEmpty + Frustum` block: canonical `Empty` has the same 512-cell result as one whole-cell fill; non-empty `Uniform` is an exact no-op because every cell is already solid; `Mixed` must remain per-cell because only its empty cells may be filled and existing material/boundary state must survive. `RegionReadView` also proves Uniform stores only material and implicit zero surface/boundary metadata, so no broader Uniform overwrite is permitted.

The same deep-interior halo proof applies to `FillIfEmpty + Frustum`: if all eight extreme centres are >32 Q4 inside the frustum, no voxel in the full block can contribute a +/-2-voxel boundary sample. Near-surface/partial blocks must retain the existing halo path.
