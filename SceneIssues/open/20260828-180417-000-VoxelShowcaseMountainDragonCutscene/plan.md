## Root cause and revision-8 topology
`experiment-010-switchback-core-gap-minimal-repro.md` isolated the third-failure cause: one X-axis ramp keeps a fixed Z footprint while the tapered core near face retreats about 69 voxels during each 46-voxel rise. `BoxEmitter.Ramp` inspection confirmed `ReverseRampBit` only reverses rise direction; it cannot make one X ramp follow Z. Therefore another offset-only fix was forbidden by the two-fix rule and structurally incapable of satisfying shell overlap at both ends.

Revision 8 keeps the deterministic tapered X-run contract and adds semantic shell-following subsegments. `MountainPathTierGeometry` records both shell-relative Z endpoints and deterministically subdivides a tier so each segment's shell retreat is less than the walking-lane overlap remaining after its exposed outer edge. Segment X/Y/Z endpoints are exact and shared by support authoring, headroom carving, path surface emission, and evidence waypoints. Both the baseline and semantic-material production catalogues consume the same segment contract; production can no longer silently retain the rejected single-ramp topology.

The regression now requires exposed-but-overlapping natural shell at both low and high ends of every tier and every segment, exact segment/tier connectivity, deterministic upper-run narrowing, shared evidence coordinates, and a lower support raster-cost proxy. Static calculation for the current authored layout is about 40 support frusta / 301M conservative proxy versus roughly 45 / 451M for the revision-6 control, well inside the 512-primitives-per-instance budget. Startup landmark provenance is revision 8, so older payloads cannot mask this realization.

## Exact visual-final failure and minimal repro
Before the next request at that point, current master `ebdc2e4f63ef...` was already an ancestor of source `08baffe6...`, so no merge was required. Exact visual-final run `33343768361` was submitted only through `ci-test/fixes/agent-4` and completed with a semantic NUnit failure, not an infrastructure/shutdown failure:

`MountainDragonNaturalSupportProgramTests.MountainPresentationHeadroomCarvingPreservesDecorativeWidthWithCenteredTraversalLane` expected centered traversal-lane carve width `16`, but production emitted width `33`.

The failure is now isolated to `WorldBuilderMountainLandmarkCatalogue.CarvePathHeadroom`. Each shell-following segment's `MountainPathSegmentGeometry.Depth` is `PathWidth + abs(EndLocalZ - StartLocalZ)`, so it intentionally includes Z retreat. The headroom implementation calculated a fixed inset from decorative path width 48, then sized the carve as `geometry.Depth - 2 * inset`. That leaks the segment's shell-retreat delta directly into clearance width; the observed 33-voxel carve is the 16-voxel lane plus about 17 voxels of retreat. This also matches the failed run's approach/base/mid captures, where large dark trench/overhang cavities dominate the mountain face. This is the demonstrated acceptance root cause; do not make another support/topology change before correcting this centered-lane raster seam.

Source `9174af573147...` made the narrow production correction: preserve shell-following segment geometry, bound the carve short axis to the configured 16-voxel lane, and center it within each segment depth. Focused exact run `33346316389` then reached the corrected width assertion but failed the next test assertion because the regression still expected the pre-segmentation carve count `13`; production correctly emitted `26` boxes, one for each authored `SegmentGeometry` piece plus final ascent and summit approach. Commit `1003689d...`, which introduced shell-following segmentation, confirms surfaces, supports, and headroom intentionally share these subsegments. Therefore this second failure is a stale regression expectation rather than another topology defect. Source `a7693c7ca367...` updates the regression to require `sum(PathTier(level).SegmentCount) + 2` without changing production geometry. Rerun that exact focused acceptance before visual-final.
