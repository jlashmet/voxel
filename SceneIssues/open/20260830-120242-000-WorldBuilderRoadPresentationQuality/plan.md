# Plan

## Acceptance
Improve the authoritative `WorldRoadNetwork` presentation without changing route/topology authority: coherent curved/diagonal edges; bounded formed cross-sections/shoulders/cut-fill; deterministic shared terrain-surface wear; topology-aware junctions; stable chunk/LOD continuity; vegetation/material/collision/destruction semantics preserved; costs within existing budgets; and exact built-player AAA validation in `KentridgePlayableSlice`.

## Current architecture / ownership
`WorldRoadProfile` + `WorldRoadResolver` own semantic route/profile intent. `WorldRoadPresentationPath` is a deterministic presentation-only refinement; `WorldRoadInfluence` and `WorldRoadNetworkVoxelCatalogue` consume it while leaving resolved route points unchanged. `WorldRoadNetworkRoute` deliberately separates authored surface radius (`CoreRadiusDm + ShoulderWidthDm`) from the broader bounded grading radius (`max(SurfaceRadiusDm, Profile.InfluenceRadiusDm)`). Each bounded piece emits one generic `EmitTerrainCorridor`; `TerrainCorridorRasteriser` evaluates the shared continuous influence, bounded crown/shoulder profile and deterministic surface-detail wear into voxel-authoritative terrain. `SmoothSurfaceVertex` remains 32 bytes and `SmoothSurface.shader` consumes the existing generic packed material/style/coverage channels. Kentridge and TopDown remain independent network consumers.

## Root cause / demonstrated defects
The original geometry defect originated before SmoothSurface: semantic influence and physical lowering were unions of segment-local straight corridor fields, so turns and true junctions could not receive continuous tangent or topology-aware shaping. The rasterizer also lacked crown/shoulder/wear response. SmoothSurface only reconstructs and shades the resulting generic voxel/material payload, so shader-only work could not recover those missing semantics.

A follow-up architecture pass found one correctness gap in the first implementation: `WorldRoadPresentationPath` supported explicit junction preservation, but production network sampling and voxel lowering called its route-only overload, so an interior point shared by another route could still be rounded away. The production path now passes the network's exact resolved-vertex junction set into semantic influence, local-frame sampling, clearance sampling, and physical piece lowering. Nearby overlap still cannot invent topology.

Exact built-player run `33340511339` at feature SHA `f30c398c17b925fd331f57c8c8c70d44f383779e` demonstrated a catalogue-budget regression (`TooManyDefinitions`): four quadratic presentation subdivisions multiplied every resolved turn into too many corridor definitions. The implementation now bounds each ordinary turn to one entry/exit chamfer without raising `FeatureBudget.MaxDefinitions`. Later player runs successfully build the 21-node/20-route Kentridge network, so the overflow symptom is removed pending final post-change budget validation.

Exact-head built-player run `33345875621` at feature SHA `4cb2625f1696ebfe4bbb26d044eed08b0e25e21e` is structurally green (3/3 PlayMode checks, real player replay, no catalogue overflow) but fails the required visual quality bar: in-town roads still read as narrow/lumpy trenches with steep stepped banks and bulbous transitions rather than a formed carriageway with clean terrain recovery. Production tracing isolates a reusable physical mismatch rather than a Kentridge-only styling issue: `WorldRoadNetworkRoute` computes distinct `SurfaceRadiusDm` and `GradeRadiusDm`, but `WorldRoadNetworkVoxelCatalogue` currently emits only `SurfaceRadiusDm` as the terrain-corridor outer radius, and `TerrainCorridorRasteriser` reuses the same 0..31 surface/material coverage to grade density. The broader configured grading envelope is therefore discarded physically, so terrain is asked to recover inside the visible shoulder instead of outside it.

## Selected approach
Keep the existing semantic/profile -> presentation path -> bounded corridor -> packed-surface production path. Curve refinement and cross-section shaping are reusable deterministic semantics, not Kentridge geometry. Junction behavior comes only from resolved network connectivity. Generic corridor wear stays in the existing persisted surface-detail channel; no road-only shader/material-instance island or vertex/storage growth is introduced.

Fix the demonstrated physical mismatch at the generic corridor boundary before changing any Kentridge-specific widths. Preserve the authored surface/material/vegetation coverage through `SurfaceRadiusDm`, while carrying `GradeRadiusDm` separately through the existing fixed-size terrain-corridor instruction/primitive payload. Density shaping should remain fully formed through the authored shoulder, then blend back to source terrain across the bounded grading transition; material/surface detail must stop at the authored shoulder so grading does not paint or suppress ecology outside it. Preserve legacy generic-corridor behavior when no separate grading radius is encoded. Add a production-path regression with intentionally different shoulder and grading radii, plus a generic fixture proving material isolation and deterministic grading. Only if exact built-player evidence still fails after this materially different fix will scene-specific width policy be reconsidered, and then only after isolating that remaining symptom in a focused fixture.

## Blast radius / cost expectations
WorldBuilder road API/lowering, generic terrain-corridor sampling/rasterization, fixed terrain-corridor operand semantics, and focused regressions are in scope. Storage format, terrain-corridor instruction length, and `SmoothSurfaceVertex` remain unchanged. Do not raise catalogue/storage/vertex budgets. The broader grade radius increases the physical clipping footprint to the radius already represented by route semantics, so re-measure catalogue definition count, primitive bounds, voxel writes, player memory and streaming/LOD behavior. Keep one bounded corridor primitive per physical piece where practical.
