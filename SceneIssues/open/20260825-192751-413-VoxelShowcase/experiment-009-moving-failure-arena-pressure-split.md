# Experiment 009 — moving traversal failure and arena-pressure split

**Hypothesis** — The current moving evidence may contain more than one failure mode. The first failing PlayMode frame should be separated from the later standalone-player arena pressure before selecting another production optimization.

**What was performed** — Rechecked the admitted targeted request `c59ca85fc9e81b09577b5a6f6c3d143d42438446` for `VoxelEngine.Tests.PlayMode.ShowcaseTraversalPerformanceTests.ContinuousPlayerTraversalNeverStuttersOrOpensNearFarGap`. Actions run `32993732467` completed with `ci/single-test: failure`; its uploaded `single.xml`, Unity log, and RealPlayer artifact were inspected. The PlayMode regression reached its fallback-safe gate, then failed on traversal frame 5 because `VoxelRenderBridge.SurfaceMetrics.VisibleSolidChunks` became zero. The test is intentionally in `m_FlyMode=true`, so its direct transform motion is not overwritten by the character motor; the zero-draw observation is genuine for that fast fly-through. The simple clipmap-entry theory was checked against the current regression suite and rejected: `SurfaceBrickDiscoveryTests.ClipmapMotionReadmitsAlreadyResidentSurfaceIntoFinerLod` already shifts the clipmap and verifies an already-resident surface is re-admitted into the finer ring.

The same CI artifact also contains the workflow's standalone-player traversal, which ran for roughly 150 seconds and did not reproduce an all-zero visible set. It generally rendered roughly 150–330 FPS while moving, with temporary missing-visible backlogs that recovered. The shared arena filled progressively; vertex occupancy reached roughly 97% by ~116 seconds, allocation failures began around ~112 seconds, and the failure counter accumulated to roughly 1.3K by the end while occupancy later moved back down as normal relief/retirement ran. This is real long-run publication pressure/fragmentation, but not evidence of a simple unreleased-lease leak. Historical experiments already rejected blindly enlarging the arena, aggressive eviction, and power-of-two lease classes; they instead identified excessive per-chunk extraction/vertex footprint, including unimplemented Transvoxel vertex reuse, as the remaining throughput lever.

**Result** — The moving request is a real failure, but its immediate frame-5 zero-draw discontinuity and its later arena-pressure behavior must not be conflated. The saved-pose replay remains stable and hole-free after convergence, so another source change is not yet justified solely by the long-run failure counter. The planned converged render-only regression is the next discriminating measurement: if it is near the historical render target, the residual player gap belongs in background extraction/publication; if it is slow, draw submission remains causal.

**What was learned** — Do not record the rejected theory that the traversal test fights `VoxelShowcase.MovePlayer`; fly mode preserves the externally advanced transform. Do not duplicate the already-covered clipmap re-admission fix. The strongest current long-run candidate remains reducing extraction/geometry footprint rather than increasing fixed arena capacity, but that should be selected only after current steady-render timing confirms raster cost is already healthy.
